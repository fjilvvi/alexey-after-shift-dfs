# АЛЕКСЕЙ: ПОСЛЕ СМЕНЫ

Браузерная мини-игра на Phaser 3, TypeScript и Vite: обслужите трёх покупателей магазина DFS, завершите смену и выполните десять успешных повторений со штангой. Алексей носит белую футболку FS и чемпионский пояс с надписью **DFS**. Обычное прохождение занимает примерно 2–3 минуты; время зависит от чтения диалогов и точности попаданий.

Игра работает на статическом хостинге без бэкенда. Изображения и шрифт находятся в проекте, музыка и звуки синтезируются локально через Web Audio. Во время игры внешние изображения и аудиофайлы не загружаются.

## Управление

На iPhone рекомендуется открыть игру в Safari и повернуть телефон горизонтально. Вертикальная ориентация поддерживается, но игровая область в ней меньше. Первый жест по кнопке запуска активирует звук; это ограничение мобильных браузеров.

| Действие | Телефон / мышь | Клавиатура |
| --- | --- | --- |
| Начать игру / тренировку | Крупная кнопка на экране | Enter |
| Двигаться в магазине | Экранные стрелки или касание пола | ← / → или A / D |
| Поговорить с покупателем | «ОБСЛУЖИТЬ» рядом с ним | E |
| Выбрать товар | Нажать нужную карточку | 1 / 2 / 3 |
| Поднять штангу | Нажать кнопку в зелёной зоне индикатора | Пробел |
| Пауза / продолжить | Кнопка II / «ПРОДОЛЖИТЬ» | P |
| Выключить / включить звук | SFX в игре или кнопка звука в шапке | — |
| Сыграть заново | «ИГРАТЬ СНОВА» на экране победы | — |

Ошибочный товар можно заменить. Промах в тренировке вызывает реакцию Алексея, после которой можно продолжать: он не блокирует игру и не засчитывается как успешное повторение. Победа наступает после десяти успешных повторений.

## Локальный запуск

Нужен Node.js 22 и npm.

```bash
npm install
npm run dev
```

Откройте `http://localhost:5173`. Чтобы проверить игру на iPhone в той же сети, используйте адрес компьютера, например `http://192.168.1.20:5173`: сервер Vite слушает все интерфейсы. Доступ зависит от настроек сети и брандмауэра компьютера.

Производственная сборка и её локальный просмотр:

```bash
npm run build
npm run preview
```

Готовые файлы находятся в `dist/`. Для воспроизводимой установки при наличии `package-lock.json` используйте `npm ci`.

## Браузерная проверка

В первом терминале оставьте работающий сервер `npm run dev`. Во втором запустите:

```bash
npm test
```

Сценарий Playwright ожидает игру на `http://127.0.0.1:5173` и Chromium по пути `/usr/bin/chromium`. Можно указать другой адрес и установленный Chromium:

```bash
GAME_URL=http://127.0.0.1:5173 CHROMIUM_PATH=/path/to/chromium npm test
```

При необходимости установите браузер Playwright командой `npx playwright install chromium`, затем передайте в `CHROMIUM_PATH` путь, который возвращает `chromium.executablePath()` из пакета `@playwright/test`.

Сценарий проходит магазин, проверяет восстановление после ошибочного товара и промаха, десять повторений, финал, повторную игру, паузу, мобильные касания, звук и отсутствие горизонтального переполнения. Скриншоты и машиночитаемый отчёт сохраняются в `artifacts/`. Наличие сценария само по себе не подтверждает успешную проверку: актуальный результат нужно смотреть в `artifacts/qa-report.json` после запуска. Эмуляция сенсорного экрана Chromium не заменяет проверку на физическом iPhone в Safari.

## Публикация на GitHub Pages

В репозитории уже есть workflow `.github/workflows/pages.yml`. В Vite используется относительная база `./`, поэтому сборка подходит и для адреса вида `https://USER.github.io/REPOSITORY/`.

1. Создайте репозиторий GitHub и загрузите в его корень содержимое этого проекта, включая `package-lock.json` и `.github/workflows/pages.yml`. Ветка для автоматической публикации — `main`.
2. В репозитории откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**. Для бесплатного GitHub Pages обычно нужен публичный репозиторий; доступность Pages для приватного зависит от вашего тарифа.
3. После push в `main` workflow **Publish game to GitHub Pages** установит зависимости, соберёт игру и опубликует `dist/`. Его можно запустить вручную через **Actions → Publish game to GitHub Pages → Run workflow**.
4. Дождитесь успешного задания `deploy`. Ссылка будет в **Settings → Pages** и в окружении **github-pages**. Откройте её на iPhone.

Пример загрузки в новый пустой репозиторий, если локальный Git ещё не настроен:

```bash
git init -b main
git add .
git commit -m "Add Alexey after shift game"
git remote add origin https://github.com/USER/REPOSITORY.git
git push -u origin main
```

Замените `USER` и `REPOSITORY` своими значениями. Для push нужны права записи в выбранный репозиторий. Готовую папку `dist/` также можно опубликовать на любом статическом хостинге; серверные функции и секреты игре не нужны.
